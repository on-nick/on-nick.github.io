Domain Reconnaissance Methodology

Category OSINT Date Apr 2026 Reading Time 9 min
Scope note: This methodology is intended for use against domains within an authorized bug bounty or CTF scope, or infrastructure the reader owns.

Introduction

Before any vulnerability testing happens, reconnaissance defines what's actually in scope and what it looks like from the outside. A structured, repeatable process here saves time and reduces the chance of missing something that turns out to matter later.

Background

A single domain rarely tells the whole story. Subdomains, forgotten staging environments, and exposed endpoints often carry more risk than the main application, simply because they get less attention. Good reconnaissance treats the domain as a starting point, not the whole target.

Methodology

  • Passive subdomain discovery first — certificate transparency logs, DNS aggregators, search engines
  • Active DNS resolution to confirm which discovered subdomains are actually live
  • Port scanning against confirmed live hosts to map exposed services
  • Lightweight HTTP probing to identify which services are web-facing and worth deeper review

Technical Analysis

A basic passive-to-active workflow, run against an in-scope lab domain:

$ subfinder -d target.example -silent
api.target.example
staging.target.example
dev.target.example
$ nmap -sV -T4 staging.target.example
PORT STATE SERVICE VERSION
443/tcp open https nginx 1.18.0
8080/tcp open http-alt Jetty 9.4

The staging subdomain here is a good example of what this process is designed to surface: a host that wasn't obviously linked from the main site, running a service on a non-standard port that might not receive the same scrutiny as the primary application.

Observations

Staging and development subdomains consistently turn up more findings than production hosts in practice — they tend to run older software, weaker access controls, or debug features left enabled. Certificate transparency logs are a particularly reliable passive source for finding them, since a TLS certificate has to be issued for the subdomain to work over HTTPS.

Lessons Learned

Keeping passive and active reconnaissance clearly separated — and doing passive discovery thoroughly before touching anything active — makes the later stages more efficient and easier to justify against a defined scope.

Conclusion

Reconnaissance is where a security assessment either gets a complete picture of the target or misses something important. A structured, repeatable process — passive first, active second, prioritized by what's actually reachable — consistently outperforms ad hoc exploration.
