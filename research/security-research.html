Vulnerability Research & Testing Methodology

How I approach web application behavior, access control, and attack surface analysis.

Focus areas

  • Access control failure patterns — how object-level and function-level authorization breaks in practice
  • Web application attack surface mapping — systematically identifying what's actually testable on a target
  • Input handling behavior — how applications process, validate, and reflect user-controlled data
  • Security testing methodology — structuring an assessment so nothing important gets skipped

Current work

Access Control Failure Patterns

Active

Building a personal reference of the ways broken object-level authorization tends to show up in real applications — inconsistent ID checks, role confusion between endpoints, and trust placed in client-supplied identifiers.

Web Application Attack Surface Mapping

Experimental

Testing a more structured process for cataloging an application's full surface — every endpoint, parameter, and role combination — before starting deeper vulnerability testing.

Note: This page tracks methodology and process, not disclosed findings. Specific vulnerabilities found during authorized engagements are reported directly to the affected program, not published here.
