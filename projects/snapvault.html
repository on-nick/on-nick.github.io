Project 01

SnapVault

An automated offline backup workflow for mobile devices — detect, connect, sync, done.

Category Python / Automation / Backup Status Working prototype
PythonAutomationDevice DetectionOffline SyncBackup Workflow

Overview

SnapVault is a Python tool that watches for mobile devices connecting to a computer over USB and automatically starts backing up their contents to local storage — no manual copy-paste, no forgetting to back up before a phone gets wiped, lost, or upgraded.

Problem

Manual phone backups are easy to skip. Most people plug a phone in, transfer a few files by hand, and forget the rest. The goal was to remove the manual step entirely: connect the device, and the backup happens on its own, offline, without relying on a cloud service.

Approach

The tool runs as a lightweight background watcher that polls for newly connected storage devices. When it detects a phone (or other USB storage device) has been mounted, it identifies whether the device has already been backed up recently, then triggers a synchronization pass against a designated backup directory.

Concurrent connections are handled explicitly — if more than one device connects around the same time, each is tracked and processed independently so one long-running transfer doesn't block detection of another device.

Architecture

Device Watcher
Polls for new USB mounts
Device Registry
Tracks known / new devices
Sync Engine
Copies new & changed files
Local Backup Store
Offline, per-device folders

Technology

  • Python for the watcher, device registry, and sync engine
  • Filesystem polling to detect newly mounted storage volumes
  • Checksum-based comparison to avoid re-copying unchanged files

Implementation

The device watcher runs a polling loop that checks for new mount points at a fixed interval. Once a device is identified, its contents are diffed against the last known backup snapshot for that device (matched by volume identifier), and only new or changed files are copied over — keeping repeat backups fast.

# simplified detection loop
while True:
devices = list_mounted_volumes()
for device in devices:
if device.id not in known_devices:
queue_backup(device)
sleep(POLL_INTERVAL)

Challenges

The trickiest part was reliably distinguishing "just connected" from "still transferring from the last session" — connecting too early can catch a device mid-mount. A short debounce window after first detection solved most of the false starts. Handling multiple simultaneous devices without one slow transfer blocking detection of a second device also required moving sync work onto its own thread per device rather than a single sequential loop.

What I Learned

This project was less about security and more about the operational discipline that security tooling also depends on: reliable detection, idempotent operations (safe to re-run without duplicating work), and graceful handling of concurrent events. Those same patterns show up constantly in reconnaissance tooling — watching for new results, avoiding duplicate work, and handling multiple targets at once.

Future Improvements

  • Optional encryption for backup storage at rest
  • Configurable backup rules (file types, folders to include/exclude)
  • A simple status CLI to show last backup time per device
