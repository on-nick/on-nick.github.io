Project 02

ScopeDork

Structured dork generation for faster, more consistent OSINT reconnaissance.

Category OSINT / Reconnaissance / Automation Status Working prototype
PythonOSINTReconnaissanceSearch AutomationGoogle DorksGitHub Dorks

Overview

ScopeDork automates the early, repetitive part of reconnaissance: building a solid set of Google and GitHub dorks for a target domain. Instead of manually assembling search operators for every engagement, the tool generates a structured, reusable set based on the domain and a handful of common exposure patterns.

Problem

Effective dorking depends on covering a wide range of search operator combinations — file types, login pages, exposed configuration files, credentials in code, and more. Doing this by hand for every target is slow and easy to do inconsistently, especially across multiple authorized engagements.

Approach

Given a target domain, ScopeDork combines it with a curated library of dork patterns — categorized by what they're looking for (exposed files, admin panels, error messages, potential credentials, API endpoints) — and outputs a ready-to-use list of search queries for both Google and GitHub.

Technology

  • Python for query generation and output formatting
  • A categorized template library for Google and GitHub dork syntax
  • Plain-text and structured output for use in other recon tooling

Implementation

Dork templates are stored as parameterized strings grouped by category (exposed files, admin interfaces, error disclosures, credential leakage, API surface). The generator substitutes the target domain into each template and produces a de-duplicated, categorized list.

# simplified template substitution
templates = load_patterns("exposed_files")
for pattern in templates:
query = pattern.format(domain=target)
results.append(query)
# site:target.example filetype:env
# site:target.example filetype:log

Challenges

Keeping the pattern library useful without becoming noisy was the main challenge — too many low-value queries bury the ones worth checking first. The categorization step (grouping by what a query is actually looking for) made it easier to prioritize which queries to run first during a real engagement.

What I Learned

Good reconnaissance tooling is as much about organizing what you already know how to look for as it is about clever automation. Structuring the dork library by intent, rather than as a flat list, made the tool far more useful in practice — and it's a pattern I've carried into other recon scripts since.

Future Improvements

  • Direct integration with search APIs for automated execution (where terms of service allow)
  • Result de-duplication and basic relevance scoring
  • Export formats for feeding into other recon tools
